# Итоговое решение о готовности выпуска

**Кейс:** DOC-17  
**Кандидат:** 1.5.0-rc1  
**Дата решения:** Текущая дата
**Ответственный за решение:** Владелец выпуска (`teacher_release`)

## 1. Решение
**СТАТУС: ОСТАНОВИТЬ ВЫПУСК (STOP).** 
Кандидат 1.5.0-rc1 не может быть передан в эксплуатацию в текущем виде. Выпуск блокируется до устранения критических пробелов в доказательной базе.

## 2. Обоснование решения
Решение основано на обязательных критериях спецификации SPEC-1.0 и фактических данных из `release_packet.json`.
1. **Восстановление (R_RESTORE):** Тест T04 имеет статус `blocked`. Отсутствует целевой ресурс для проверки. В пакете нет сведений о предыдущих испытаниях восстановления. Мы не можем подтвердить, что система уложится в RTO 20 минут и RPO 15 минут. Любой подтвержденный дефект потери данных блокирует выпуск.
2. **Производительность (R_PERFORMANCE):** Тест T05 имеет статус `not_run`. У нас нет доказательств, что система выдержит нагрузку (успех ≥ 99%, p95 ≤ 800 мс). Согласно спецификации, пустой тест не считается успешным.
3. **Документация:** Руководство оператора в пакете устарело (версия 1.4.2) и содержит опасный совет, ведущий к созданию дублей заявок при сетевом тайм-ауте. Хотя это не является техническим блокером самого кода, выпуск с такой документацией запрещен.

## 3. Условия для пересмотра решения
Решение может быть пересмотрено только после выполнения следующих минимальных действий:

| Действие | Ответственный | Требуемое доказательство |
| :--- | :--- | :--- |
| **1. Завершить тест R_RESTORE.** Предоставить стенд, провести восстановление из бэкапа `B-1755`. | Владелец тестирования (`student_tester`), Поддержка | Лог успешного восстановления, подтверждение RTO ≤ 20 мин, RPO ≤ 15 мин, сверка данных с контрольным набором. |
| **2. Провести тест R_PERFORMANCE.** Запустить нагрузочный профиль (20 операторов, 1000 заявок). | Владелец тестирования (`student_tester`) | Отчет с метриками: доля успешных операций ≥ 99%, p95 ≤ 800 мс. |
| **3. Обновить документацию.** Заменить руководство 1.4.2 на исправленную версию (фрагмент подготовлен в `documentation_changes.md`). | Владелец выпуска (`teacher_release`) | Факт включения новой версии руководства в пакет. |

## 4. Ограничения и допущения
- Фактический хеш пакета не вычислялся, так как сам архив отсутствует. Контроль целостности считается неподтвержденным.
- Идентификаторы `DEMO-COMMIT` и `synthetic-log` являются учебными маркерами и не подтверждают реальных действий в Git.
- Решение принято на основе анализа синтетического пакета DOC-17.
